# Results — 2026-11

Results of the rules experiment's full run (18 runs: tasks T1–T6 in
conditions A, B and C, one run each) and of its pilot, all run on
2026-11-24. The numbers come from the run transcripts (`collect_metrics.py`),
from the acceptance tests and ATC runs of the evaluation session, and from
`rubric_scan.py`. The per-run evaluation files, the transcripts and the
sources the runs generated are not published. Per-run metrics:
[experiment/results/2026-11/metrics.csv](metrics.csv).

This file adds numbers up and puts them side by side; it adds no new
measurement. One run per task and condition: the numbers describe these 18
runs, not a population.

[experiment/conditions/C/CLAUDE.md](../../conditions/C/CLAUDE.md), frozen as

### Deviations and recorded facts

- **Validity checks (V-1, V-2, V-3):** no deviation in any of the 18 runs.
  Every `permission-mode` record is `dontAsk`; calls outside the allowlist
  are only `ToolSearch` (1–3 per run) and, from T2, one `Read` of the run's
  own `TASK.md`; no `Skill` call; no question to the user (R-C14 0).
- **Task delivery:** T1 pasted, T2–T6 from `TASK.md` (K20). Within a task
  all three conditions got the same delivery.
- **`runs.csv` end fields:** B2 (K25) and C4, B5, C5, A5, C6, A6, B6 (after
  the evaluation) had empty `end_time`, `end_reason` and `questions_answered`. They
  were filled from the local time of each transcript's last record (a
  `system` `turn_duration` record), `done`, `0`. M-3 comes from the
  transcripts, not from these fields.
- **B3 / A4 times:** B3's recorded end time lies after A4's recorded start;
  B3's transcript's last record has the same time as A4's start.
- **Release file (R-C9):** `src/objectReleaseInfo_BTPLatest.json` from SAP's
  public repository [SAP/abap-atc-cr-cv-s4hc](https://github.com/SAP/abap-atc-cr-cv-s4hc),
  commit `c482599c2525f40377816cf1419ea5a7728c5534` (2026-10-06), fetched
  during the evaluation; it is not republished here.
- **K21 after part 1:** the T2 acceptance test was changed after part 1;
  the three T2 shells were updated and run again; both results are reported.
- **Runs that started an ATC run themselves:** B1, B2, C2, C5, C6
  (`atc_runs` 1 each); C5 and C6 without a variant. No run executed a unit
  test (`unit_test_runs` 0).

### Known limits

- **One run per cell.** 18 runs, one per task and condition; model output
  varies between runs, so differences can be run-to-run variation.
- **One model.** All runs used `claude-opus-5-5` with Claude Code 2.1.331.
- **Specs fix the interfaces.** Design rules about dependencies (Rule 5.4,
  Rule 8.17) cannot vary.
- **Acceptance tests use doubles.** T1 an API double, T2 sender and setup
  doubles, T3 the SQL test double and authorization test environment, T4 an
  SQL test double and a lock double, T5 and T6 no dependency. The T4 test
  cannot see an empty lock mode in the generated module; R-T4e is read from
  the module by the evaluation.
- **Test change after part 1 (K21).** Before K21, A2 and C2 failed
  `note_is_text_not_markup` on the `<b>` of their own HTML template. After
  K21 all three T2 runs pass. Negative check: a probe that leaves the note
  unescaped (NEG) fails `note_is_text_not_markup` (expected -1, actual 42),
  a probe that escapes it with `e_xss_ml` (ESC) passes all 7 methods
  (negative check of the evaluation).
- **T3** depends on the tester's own `S_CARRID` authorizations; an overall
  `PASSED` cannot tell a skipped method from a passed one.
- **The scan is pattern-based** (R-C5 checks the next statement only; R-T3a
  matches the literal only, K27; R-C9 does not look at built-in functions,
  K28).
- **Runs could not execute tests** (unit test tool denied), in all
  conditions.
- **Account-level context** (synced skills, claude.ai connectors, session
  context) reached every run equally (K17).
- **Same operator, same day, two systems;** rotation reduces but does not
  remove order effects.
